# Описание окружений и переменных

## Схема развёртывания

```
project/  ──git2test──▶  TEST  ──test2beta──▶  BETA  ──beta2prod──▶  PROD
(исходники)              (тест)                (бета)                (продакшн)
```

Код всегда движется в одном направлении: **source → test → beta → prod**.
Обратное продвижение не предусмотрено.

## Окружения

| Окружение | Назначение | База данных |
|-----------|-----------|-------------|
| **TEST** | Тестирование новых изменений. Обновляется из git автоматически или вручную | Отдельная (своя) |
| **BETA** | Предпродакшн-проверка. Обновляется из TEST | Общая с PROD |
| **PROD** | Боевой сервер. Обновляется из BETA с двойным подтверждением | Общая с BETA |

> **Важно:** BETA и PROD используют одну и ту же базу данных. Это значит, что
> миграции БД, применённые на BETA, сразу видны на PROD. Планируйте миграции
> с учётом обратной совместимости.

## Переменные `.env`

Файл `.env` создаётся скриптом `install.sh` и **не коммитится** в репозиторий
(добавлен в `.gitignore`).

### Окружения

| Переменная | Описание | Пример | Откуда взять |
|-----------|----------|--------|-------------|
| `TEST_DOMAIN` | Домен тестового сервера | `test.myapp.com` | DNS / панель хостинга |
| `TEST_FOLDER` | Абсолютный путь к папке TEST на сервере | `/var/www/test` | Настройки веб-сервера |
| `BETA_DOMAIN` | Домен бета-сервера | `beta.myapp.com` | DNS / панель хостинга |
| `BETA_FOLDER` | Абсолютный путь к папке BETA | `/var/www/beta` | Настройки веб-сервера |
| `PROD_DOMAIN` | Домен продакшн-сервера | `myapp.com` | DNS / панель хостинга |
| `PROD_FOLDER` | Абсолютный путь к папке PROD | `/var/www/prod` | Настройки веб-сервера |

### База данных: BETA + PROD (общая)

| Переменная | Описание | Пример | Откуда взять |
|-----------|----------|--------|-------------|
| `SHARED_DB_HOST` | Хост БД | `db.myhost.com` | Панель управления БД |
| `SHARED_DB_NAME` | Имя базы данных | `app_production` | Создаётся администратором БД |
| `SHARED_DB_USER` | Пользователь БД | `app_user` | Создаётся администратором БД |
| `SHARED_DB_PASS` | Пароль БД | — | Создаётся администратором БД |

### База данных: TEST (отдельная)

| Переменная | Описание | Пример | Откуда взять |
|-----------|----------|--------|-------------|
| `TEST_DB_HOST` | Хост тестовой БД | `localhost` | Панель управления БД |
| `TEST_DB_NAME` | Имя тестовой БД | `app_test` | Создаётся администратором БД |
| `TEST_DB_USER` | Пользователь тестовой БД | `test_user` | Создаётся администратором БД |
| `TEST_DB_PASS` | Пароль тестовой БД | — | Создаётся администратором БД |

### Git

| Переменная | Описание | Пример | Откуда взять |
|-----------|----------|--------|-------------|
| `GIT_REPO_URL` | URL git-репозитория | `git@github.com:user/repo.git` | GitHub / GitLab |
| `GIT_BRANCH` | Ветка для деплоя на TEST | `main` | Определяется командой |

## Связь папок и версий

### `project/` — исходный код

Папка `project/` в репозитории — это **эталонная копия** исходного кода проекта.
При развёртывании её содержимое копируется в папки окружений.

### `manifest.json` — версия проекта

Каждая копия проекта содержит файл `manifest.json`:

```json
{
  "version": "1.2.0",
  "build": "045",
  "date": "2026-03-18",
  "description": "Описание релиза"
}
```

- **version** — семантическая версия (MAJOR.MINOR.PATCH)
- **build** — номер сборки (инкрементируется при каждом обновлении)
- **date** — дата последнего обновления
- **description** — краткое описание версии

Скрипт `status.sh` читает `manifest.json` из каждой папки окружения и показывает
сводную таблицу версий.

## Что исключается при синхронизации

При обновлении (`git2test`, `test2beta`, `beta2prod`) следующие файлы и папки
**не перезаписываются**:

| Исключение | Причина |
|-----------|---------|
| `config.*` | Конфигурация специфична для каждого окружения (БД, домен) |
| `.env` | Переменные окружения |
| `uploads/` | Пользовательские загрузки |
| `storage/` | Кеш, сессии, логи |

Это гарантирует, что настройки каждого окружения и пользовательские данные
сохраняются при обновлении кода.

## Автономная установка

`install.sh` можно запускать **без предварительного клонирования** репозитория:

1. Скачайте `install.sh` любым способом (curl, wget, браузер)
2. Запустите: `bash install.sh`
3. Скрипт спросит URL репозитория, ветку и папку для клонирования
4. Сам клонирует репозиторий и проведёт настройку

При запуске из клонированного репозитория скрипт автоматически определяет
это по наличию `common.sh` и `project/` рядом, и работает в обычном режиме.

## Подготовка сервера

Перед запуском `install.sh` необходимо:

1. Создать папки для каждого окружения (например, `/var/www/test`, `/var/www/beta`, `/var/www/prod`)
2. Настроить веб-сервер (nginx/apache) для каждого домена
3. Создать базы данных и пользователей
4. Установить на сервер: `bash`, `rsync`, `git`
5. Убедиться, что у пользователя есть права на запись в папки окружений
